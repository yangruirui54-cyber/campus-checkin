# Campus Check-in｜校园活动签到练习

使用 Python 标准库和 SQLite 制作的命令行练习原型。以校园活动为场景，练习数据存储、输入校验、重复记录处理与文件导出。

**当前状态：AI 辅助生成的学习起点；尚未接入区块链，未部署到 Monad，也不是生产系统。** 使用者应先运行、理解并修改代码，再根据实际参与情况介绍个人贡献。

## 已实现

- 创建和列出活动。
- 使用参与者代号签到，并记录 UTC 时间。
- 同一活动、同一代号不能重复签到；不同活动互不影响。
- 查询记录并导出 CSV；导出不会覆盖同名文件。
- 数据保存在本机 SQLite 文件中。

## 快速运行

需要 Python 3.10 或更新版本，无需安装第三方依赖。在项目文件夹打开终端，依次执行：

```powershell
python app.py create "校园 Web3 交流会"
python app.py events
python app.py checkin 1 student-a
python app.py checkin 1 student-a
python app.py checkin 1 student-b
python app.py records 1
python app.py export 1 attendance-demo.csv
python -m unittest -v
```

示例假设数据库为空，首个活动编号为 1；已有数据时请用 create 返回的编号替换。重复运行导出时换一个文件名。Windows 上如果 python 不可用，可尝试 py。

首次签到输出 `Checked in.`，第二次显示已经签到，查询总数应为 2。退出程序后再查询，数据仍然存在。

## 代码怎么读

1. `connect`：建立数据库连接，创建活动表和签到表。
2. `create_event`：插入活动并返回其编号。SQL 中的问号通过参数传值。
3. `check_in`：先确认活动存在，再写入签到；数据库的 UNIQUE 约束防止重复。
4. `records`：只查询指定活动的记录。
5. `export_csv`：将查询结果输出为 CSV，方便查看与演示。
6. `main`：解析终端命令，调用对应函数。

## 边界与后续计划

参与者代号由操作者输入，不验证真实身份，所以目前不能防冒名签到；本地数据库也可以被修改。它适合作为学习演示，没有登录、多人在线访问或链上凭证。

后续可以探索钱包签名、活动方授权及参与凭证，但先明确这些问题：谁能创建活动？谁能批准签到？哪些数据真的需要公开上链？不应把姓名、学号等个人资料直接写入公开区块链。未来如接入 Monad，须以实际完成的测试网部署与交易记录为准。

## 建议你亲手完成的一次修改

增加 `count` 命令：输入活动编号，只输出签到人数。可以参考 `records` 的实现。修改后再验证重复签到不会增加人数。这是一个范围清楚、能解释个人贡献的练习；未完成前不要在报名中声称已完成。
